# תמה — סביבת עבודה לקורפוס מחקרי

אפליקציה בעברית לניהול פוסטים, תמות וציטוטים, עם חיפוש וסינון, ספר קודים, גיבוי JSON וייצוא CSV. ניתן לעבוד מקומית או לחבר ל־Cloud Firestore.

## 1. שמירת הנתונים הקיימים

לפני מעבר לענן, פתחו את הגרסה שבה כבר עבדתם והורידו גיבוי JSON. שמרו אותו מחוץ למאגר GitHub. קבצי הגיבוי מהגרסה הקודמת נתמכים. הנתונים המקומיים הקודמים נשארים באותו מפתח אחסון, למרות שינוי שם האפליקציה.

## 2. יצירת Firebase
  
1. פתחו https://console.firebase.google.com וצרו פרויקט בשם `thema`. אין צורך ב־Analytics עבור האפליקציה.
2. ב־Project overview הוסיפו אפליקציית Web באמצעות הסמל `</>`. אין צורך להפעיל Firebase Hosting: האתר יתפרסם ב־GitHub Pages.
3. ב־Project settings → General → Your apps מצאו את אובייקט `firebaseConfig`.
4. מלאו את ארבעת הערכים בקובץ `firebase-config.js`: `apiKey`, `authDomain`, `projectId`, `appId`. אלו פרטי הגדרה ציבוריים שמיועדים לקוד הדפדפן, לא מפתח מנהל. אין להעלות קובץ Service Account או Private key.
5. פתחו Authentication → Get started → Sign-in method והפעילו **Anonymous** בלבד. המשתמש לא יקבל מסך כניסה: האפליקציה תבצע זיהוי אנונימי אוטומטי ברקע, ללא חשבון Google.
6. פתחו Firestore Database → Create database, ובחרו Standard edition אם נשאלתם. בחרו אזור אחסון שמתאים למחקר, והתחילו במצב Production. האזור נקבע בזמן יצירת המסד.
7. בלשונית Rules החליפו את הכללים בתוכן המלא של `firestore.rules`, ולחצו Publish. אל תבחרו כללים שמאפשרים גישה לכל המסד. הכללים שהכנו מאפשרים גישה רק בנתיב של קישור סודי ומונעים רשימת כל סביבות העבודה.
8. אם Firebase מבקש להגדיר Authorized domains, הוסיפו ב־Authentication → Settings את הדומיין של האתר, לדוגמה `YOURNAME.github.io` (בלי נתיב המאגר).

תיעוד: https://firebase.google.com/docs/web/setup
זיהוי אנונימי: https://firebase.google.com/docs/auth/web/anonymous-auth
כללי גישה: https://firebase.google.com/docs/firestore/security/get-started

## 3. העלאה ל־GitHub

1. חלצו את `thema-github.zip` לתיקייה. ודאו שקיימת בה גם התיקייה הנסתרת `.github`.
2. צרו מאגר GitHub, לדוגמה `thema`, והעלו את **תוכן התיקייה לשורש המאגר**. `index.html` צריך להיות בשורש, ולא בתוך תיקיית corpus נוספת. אפשר להשתמש ב־GitHub Desktop כדי לכלול גם את `.github`.
3. ודאו ש־`firebase-config.js` מכיל את ההגדרות שמילאתם ושכל הקבצים נשמרו בענף `main`.
4. ב־Settings → Pages בחרו Source: **GitHub Actions**.
5. בלשונית Actions פתחו `Publish app to GitHub Pages` ולחצו Run workflow אם הפרסום טרם התחיל. המתינו להצלחה; כתובת האתר תופיע ב־Settings → Pages ובתוצאת הפרסום.
6. הקוד מכין לפרסום רק את קובצי האפליקציה. כללי Firestore נשארים בקוד אבל יש לפרסם אותם בנפרד ב־Firebase כפי שתואר למעלה.

תיעוד: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

## 4. יצירת קישור הקורפוס

1. פתחו את כתובת GitHub Pages. אין לפתוח קובץ `file://` לצורך חיבור לענן.
2. לחצו **יצירת קישור סודי לקורפוס חדש**. האפליקציה תוסיף לכתובת `#` ואחריו מחרוזת אקראית באורך 64 תווים. זהו מפתח הגישה לקורפוס.
3. שמרו את **הקישור המלא** בסימנייה פרטית. לחצו ״העתקת קישור גישה״ כדי לפתוח את אותו קורפוס ממכשיר אחר. הכתובת ללא החלק שאחרי `#` לא פותחת את הקורפוס.
4. הוסיפו פוסט או תמה ושמרו. החיווי צריך להראות **נשמר בענן**. פתיחת הקישור המלא במכשיר נוסף צריכה להציג אותם.
5. להעברת הנתונים הקיימים: השתמשו ב״טעינת גיבוי״ ובחרו את JSON שהורדתם לפני המעבר. הפעולה מחליפה את תוכן הקורפוס בענן לאחר אישור. אם הנתונים המקומיים קיימים באותה כתובת, יוצג גם כפתור העברה ייעודי.
6. הורידו גיבוי גם בהמשך. יש לרענן את הדף כדי לקבל שינויים שנעשו במכשיר אחר. אם מנסים לשמור עותק מיושן, האפליקציה חוסמת את השמירה ומבקשת חיבור מחדש, במקום לדרוס את הקורפוס. העתיקו שינויים מהטופס לפני חיבור מחדש.

## מודל הגישה והמגבלות

- כל מי שמחזיק בקישור הסודי יכול לקרוא, לערוך ולמחוק את התוכן. אין זהות משתמש, הרשאות צפייה בלבד או דרך לחסום אדם מסוים. כתובת האתר הרגילה אינה סוד; המחרוזת האקראית היא הסוד. זיהוי אנונימי לבדו אינו מגביל גישה לקורפוס.
- אל תכניסו את הקישור הסודי לקוד, ל־README, למאגר ציבורי או לצילום מסך. האפליקציה מגדירה no-referrer ואינה משלבת Analytics. קישור סודי שאבד אינו ניתן לשחזור מתוך האתר; מנהל פרויקט Firebase יכול למצוא את מזהה סביבת העבודה במסד. קישור שדלף דורש יצירת סביבת עבודה חדשה, העברת גיבוי ומחיקת הסביבה הישנה ממסוף Firebase.
- הרשאות מנהל בפרויקט Firebase מאפשרות גישה לנתונים בלי הקישור. המודל הוא הרשאה לפי החזקת קישור, ולא הצפנה מקצה לקצה.
- במצב ענן אין שמירת קורפוס קבועה בדפדפן. טעינה ושמירה דורשות אינטרנט, וכשל שמירה מוצג במפורש. טופס שלא נשמר יאבד בסגירת הדף. בעת ניתוק ממושך רעננו לפני ניסיון נוסף.
- כל פוסט ותמה הם מסמך נפרד. פעולת ייבוא או החלפה מוגבלת ל־450 רשומות שהשתנו; קורפוס גדול יותר דורש כלי ייבוא ייעודי. חיפוש מסנן את הקורפוס שנטען לזיכרון.
- אין כרגע העלאת תמונות, איסוף אוטומטי מפייסבוק או סיווג AI. השדה הוויזואלי מסמן נוכחות בלבד.
- עקבו אחר Usage ב־Firebase. המערכת משתמשת בקריאות וכתיבות Firestore ובזיהוי אנונימי; חלות המכסות והתמחור של הפרויקט שלכם.

## עבודה מקומית בלי Firebase

כאשר `projectId` ריק, האפליקציה נשארת במצב מקומי עם localStorage. פתחו `index.html` בדפדפן, או הפעילו שרת מתוך התיקייה באמצעות `python3 -m http.server 4173`. הנתונים תלויים במכשיר, בדפדפן ובכתובת שבה השתמשתם. מחיקת נתוני הדפדפן או גלישה פרטית עלולות למחוק אותם. גופן Google Fonts נטען חיצונית; להסרה מחקו את שורת ה־import בתחילת style.css.

## בדיקה לפני שימוש בחומרי המחקר

1. שמרו פוסט בדיקה ותמה, פתחו את אותו קישור בדפדפן אחר ובדקו שהמידע מופיע.
2. ערכו ושמרו במכשיר אחד, ונסו לשמור במכשיר השני ללא רענון: השמירה הישנה אמורה להיחסם.
3. פתחו את הכתובת ללא החלק הסודי: לא אמור להופיע הקורפוס.
4. נתקו רשת ונסו לשמור: לא אמור להופיע חיווי ״נשמר בענן״.
5. הורידו גיבוי ובדקו שחזור בסביבת עבודה חדשה לפני שימוש בחומר אמיתי.

לא בוצעה בדיקת אינטגרציה מול פרויקט Firebase אמיתי: יש להשלים את הבדיקה לאחר מילוי ההגדרות ופרסום הכללים.
